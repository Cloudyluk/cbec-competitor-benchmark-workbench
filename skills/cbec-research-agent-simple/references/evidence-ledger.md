# 证据账本：定级细则与操作规范

## 账本字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `fact_id` | 是 | `F001` 递增，报告中引用用此编号 |
| `category` | 是 | identity / financial / operational / product / supply_chain / compliance / market / people / capital |
| `claim` | 是 | 一句话事实陈述，**必须带口径**（时间点、货币、地区、统计范围） |
| `level` | 是 | VERIFIED / STRONG / WEAK / UNVERIFIED / CONFLICT |
| `source_type` | 是 | L1_official / L2_platform / L3_authoritative / L4_tool_or_community |
| `source_url` | 是 | 完整 URL；无 URL 的来源写明获取方式（如"线下问询"） |
| `accessed_at` | 是 | 实际访问日期 `YYYY-MM-DD` |
| `source_quote` | 是 | 来源原文摘录（≤200 字），用于复现 |
| `conflicts_with` | 否 | 与之冲突的 fact_id，逗号分隔 |
| `data_as_of` | 数字/时点型事实必填 | 该数字真实有效的截至时点，格式 `YYYY-MM` 或 `YYYY-Qn`（如 `2026-Q1`、`2025-12`）。**不是**访问日期。缺失视为口径不全 |
| `metric_type` | 数字/时点型事实必填 | 指标衰减速度，用于新鲜度计算：`fast` / `medium` / `slow` / `structural` / `na`（详见 `references/freshness-policy.md`） |
| `note` | 否 | 口径说明、局限、后续验证方式 |

> **时效与新鲜度**：除了下面的"时效规则"（超龄降级），每条带数字的事实还须标注 `data_as_of` 与 `metric_type`，
> 由 `scripts/ledger_check.py` 自动计算新鲜度（FRESH/AGED/STALE）并据此约束决策上限。详见 `references/freshness-policy.md`。

## 五级判定细则

### VERIFIED 已核验

满足以下任一条：
- 单一 **L1 官方登记来源**（政府工商/商标/海关/监管机构/交易所披露文件）
- 单一 **L2 平台一手来源**（平台店铺页、商品页、官方公告、平台披露的卖家信息）
- **≥2 个相互独立**的 L3 来源，内容一致（"独立"指不同机构且非互相转载）

且必须同时满足：有可访问 URL、有访问日期、有原文摘录、他人可复现。

**不构成独立**：同一集团旗下多家媒体、转载同一通稿的多个站点、引用同一份第三方报告的多篇文章。

### STRONG 强推断

- 单一 L3 权威来源（主流财经媒体原创报道、券商/咨询机构署名报告、上市公司年报中的表述）
- 多个 L4 来源高度一致，且存在完整逻辑链（例如三个独立数据工具对同一 ASIN 的月销估算落在同一量级）
- 由 VERIFIED 事实经明确、可复述的推理链得出的结论（推理链必须写在 `note` 中）

### WEAK 弱推断

- 单一 L4 来源：卖家精灵 / Jungle Scout / Helium 10 / Keepa / Kalodata / FastMoss / 蝉妈妈 / SimilarWeb 等工具估算
- 行业惯例外推（"该类目一般毛利 35%"）
- 单点样本（一条评价、一次抽查）
- 时效超过 24 个月的旧数据，即使原来级别更高，也降至 WEAK 并注明原级别

### UNVERIFIED 未证实

- 主体自述：官网介绍、招商材料、销售话术、路演 PPT、公众号推文
- 无署名的行业传闻、社群消息
- 有主张但检索后找不到任何第三方佐证

**重要**：UNVERIFIED 不等于"假"，只等于"未被证实"。要在报告中原样保留并标注，而不是删除或采信。

### CONFLICT 冲突

≥2 个来源对同一事实给出互相矛盾的说法。处理规范：

1. **不取平均、不择优采信、不静默丢弃**
2. 在账本中为每一方各建一行，`level` 均标 CONFLICT，用 `conflicts_with` 互相指向
3. 在 `30_conflicts.md` 中记录：冲突项 / A 方说法+来源+级别 / B 方说法+来源+级别 / 可能原因（口径不同？时点不同？统计范围不同？）/ 如何证伪
4. 常见"伪冲突"先排除：财年 vs 自然年、GMV vs 净销售额、含税 vs 不含税、合并报表 vs 单体、平台口径 vs 卖家口径、汇率与时点差异

> 冲突消解的具体定级矩阵（官方/平台/二手/工具 各层级对撞如何处置、有效等级 k 取低者）见 `references/conflict-resolution.md`。

## 口径规范（数字型事实）

任何数字必须带全以下要素，缺项则**降一级**：

- **时间**：时点还是时段？具体到月。
- **货币与汇率**：币种 + 若做过换算需注明汇率与日期。
- **地区**：全球 / 单一站点 / 单一市场。
- **统计范围**：单店 vs 全店铺矩阵；单 SKU vs 全类目；含退货扣减与否。
- **口径类型**：GMV / 净销售额 / 出货量 / 曝光 / 场观（注意场观是累计观看人次，非同时在线）。

反例：`月销 5000 件` → 降级。
正例：`该 ASIN 2026-05 在 Amazon US 站的月销量约 5000 件（Keepa BSR 推算，未扣退货）` → WEAK，口径完整。

## 时效规则

| 数据年龄 | 处理 |
|---|---|
| ≤6 个月 | 正常定级 |
| 6-24 个月 | 保留级别，`note` 标注数据日期 |
| >24 个月 | 强制降至 WEAK，注明原级别与原因 |
| 结构性事实（成立日期、注册号、历史诉讼） | 不受时效影响 |

## 置信度传导

**结论的置信度 = 支撑它的最弱一条关键证据的等级。**

例：结论"该供应商具备年产 500 万件产能"依赖 F012（VERIFIED，厂房面积）+ F013（WEAK，产能自述换算）→ 结论级别为 WEAK。

在报告中，每条结论后括注支撑 fact_id 及其最低级别，例如：`（F012 VERIFIED / F013 WEAK → 结论 WEAK）`。

## 校验

```bash
python scripts/ledger_check.py research/<slug>/10_evidence_ledger.csv
```

输出：字段完整性问题、非法 level 值、缺失 URL/日期、各级别分布、核心类目覆盖情况、**决策等级上限提示**。
