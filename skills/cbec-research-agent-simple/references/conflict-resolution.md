# 多源信息融合与冲突消解（Multi-source Fusion & Conflict Resolution）

本模块把"同一事实多源矛盾 / 跨层级来源并存时如何定级"从隐含经验提升为**显式、可复用的处置矩阵**。它是 P2/P3 的一级能力，不是顺手处理。

## 一、何时启用

出现以下任一情况时，必须按本矩阵处置，而不是凭直觉取一个"看起来更对"的源：

- 同一事实有 ≥2 个来源说法互相矛盾（`conflicts_with` 非空）；
- 同一事实存在 L1/L2 官方源与 L3/L4 二手/估算源并存，且数值不同；
- 多个 L4 工具估算落在不同量级；
- 用户给的"已知数据"与本流程联网核验结果不一致。

## 二、优先级总原则

1. **来源层级优先**：L1 官方登记 / 交易所披露 ＞ L2 平台一手 ＞ L3 权威二手（原创报道 / 署名报告） ＞ L4 工具估算 / 社区。
2. **同层以"新"优先**：`data_as_of` / `reported_at` 更近者优先；同口径、同时点且相互独立，则 ≥2 独立源可升级一级（如 2 个独立 L3 → 视为 VERIFIED 等效）。
3. **官方对官方不自动采信**：L1 vs L1 矛盾 = 无法自动分辨，必须升级 CONFLICT 交用户，并提示"财务重述 / 口径变更 / 数据造假"可能（记 Y21/Y27）。
4. **先排除伪冲突**：财年 vs 自然年、GMV vs 净销售额、含税 vs 不含税、合并 vs 单体、平台 vs 卖家口径、汇率与时点差异。伪冲突归一后按真实口径定级，不计入 CONFLICT。

## 三、冲突消解矩阵

| 冲突类型 | 来源组合 | 处置 | 有效等级(k) | 记账方式 |
|---|---|---|---|---|
| 官方对官方 | L1 vs L1（同事实矛盾） | 不自动采信，并列 + 升级 CONFLICT，提示用户核实（疑重述/造假） | CONFLICT | 双方各一行 CONFLICT，互相 `conflicts_with`；`note` 标"待用户核实" |
| 官方/平台 vs 权威二手 | L1/L2 vs L3 | 以 L1/L2 为准；L3 作"差异备注"，触发 Y21/Y27 关注口径/真实性 | 取 L1/L2 等级 | 主行 VERIFIED/STRONG；副行 STRONG 且 `conflicts_with` 指向主行，`note` 标"差异待证" |
| 官方/平台 vs 工具估算 | L1/L2 vs L4 | 以 L1/L2 为准；L4 仅作量级佐证，不采信为事实 | 取 L1/L2 | 主行 VERIFIED；L4 行 WEAK，`note` 标"差异在估算误差内/外" |
| 工具对工具 | L4 vs L4 | 不取平均、不择优；报"区间/有争议"，量级一致可给量级区间 | WEAK（区间） | 双方各 WEAK，互相 `conflicts_with`，`note` 给量级区间 |
| 权威二手对权威二手 | L3 vs L3（独立） | 无法互证则并列；差异小可各自 STRONG，差异大升级 CONFLICT | 取低者 / CONFLICT | 各自 STRONG，互相 `conflicts_with`；差异大则 CONFLICT |
| 时点/口径伪冲突 | 实质一致仅口径不同 | 先排除伪冲突（见第二节第 4 条），归一后按真实口径定级 | 视归一后 | 一行，`note` 标"已排除伪冲突：…" |

## 四、对决策的影响

- 任一**核心事实**为 CONFLICT（或 UNVERIFIED）→ 决策上限「补充尽调」（`decision-rubric.md` 步骤 2）。
- 大量 L3/L4 并存且未消解 → 计黄旗 Y27（多源未解决冲突）。
- L1/L2 与 L3 差异且无法解释 → 计黄旗 Y21（收入/数据口径不清）或 Y27，提示核实。

## 五、账本落地

- 每个冲突事实在 `10_evidence_ledger.csv` 至少两行，互相 `conflicts_with`。
- 有效等级 k 取冲突各方中**较低者**（保守），并在 `note` 写明消解依据（哪条原则、为何取此源）。
- `30_conflicts.md` 用矩阵行记录：冲突项 / 各方说法 + 来源 + 级别 / 可能原因 / 证伪路径。
